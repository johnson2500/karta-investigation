Karta + Grove + Kueue

Minimal Helm showcase: schema maps, clique topology, and quota admission on one OpenShift cluster — without wiring Grove into Kueue.

Demo folder: examples/karta-grove-kueue

Roadmap question

Can Karta, Grove, and Kueue coexist?

Can we run Karta (maps), Grove (cliques), and Kueue (queues) on one cluster so stakeholders see each role clearly?

Yes — as independent layers.

This chart shows coexistence. Native Grove→Kueue scheduler backends are out of scope; paths stay independent.

Separation of concerns

What each piece owns

PieceRole in this demoDoes not
Karta Maps Grove PodCliqueSet and batch/v1 Job Admit jobs or place pods
Grove Creates pods from a tiny PodCliqueSet Parse arbitrary CRDs or own quota
Kueue Admits sample Jobs via LocalQueue / ClusterQueue Define clique topology

Mental model

Two paths, one Job map

PATH A
Grove Karta PCS map → PodCliqueSet → worker pods on default-scheduler
PATH B
Kueue Jobs Karta Job map → kueue-demo-job + openshift-batch-job → admitted
  • One grove-kueue-batch-job-v1 Karta covers every batch/v1 Job — no map per Job name.
  • Paths are independent: no Grove→Kueue glue in this chart.

Karta · batch/v1 Job

What the Job map declares

Pod template.spec.template
Scale.spec.parallelism // 1
Suspend / resume.spec.suspend (same field Kueue uses)
Gang groupbatch.kubernetes.io/job-name
  • statusMappings normalize Complete / Failed / Suspended into portable phases.
  • OpenShift-styled Jobs need no separate map.

Karta · Grove PodCliqueSet

What the PCS map declares

Root kindgrove.io/v1alpha1 PodCliqueSet
ChildrenPodClique · PodCliqueScalingGroup
Pod fieldsfragmentedPodSpecDefinition (claims, affinity, …)
Gangpart-of + podcliqueset-replica-index
  • Platforms walk Grove without hard-coding CRD paths in Go.
  • Grove still owns lifecycle; Karta only describes schema.

Hands-on

Install path

1. Operators ./scripts/install-operators.sh
Karta · Grove (default-scheduler) · Kueue
2. Demo chart helm upgrade --install demo . -n demo --create-namespace
  • Verify: oc get karta · podcliqueset · workloads · jobs
  • Expect: Grove pods Running; both Job Workloads Admitted.

Verify

What “good” looks like

  • oc get karta → grove-kueue-podcliqueset-v1alpha1 + grove-kueue-batch-job-v1
  • oc get podcliqueset -n demo → grove-demo; pods Running
  • oc get workloads -n demo → Admitted for both sample Jobs
  • Jobs unsuspend and complete under Kueue control
Not proven here: Grove PCS admitted by Kueue, or KAI topology. Sibling charts cover those angles.

Takeaways

What to remember

  1. Coexistence works — Karta, Grove, and Kueue on one cluster with clear roles.
  2. One Job map covers generic and OpenShift-styled batch/v1 Jobs.
  3. PCS map lets platforms read Grove without hard-coded Go paths.
  4. Paths stay independent in this demo — no Grove→Kueue backend required to prove the point.

Map · shape · admit — three layers, one cluster.
