Schema translation for PyTorchJob on the default kube-scheduler — proving placement stays pluggable.

Demo folder: examples/karta-decoupled-scheduler

Roadmap question

Hard dependencies on KAI?

Are there any hard dependencies on KAI for Karta to work?

No.

Karta registers declarative maps. Pods schedule through whatever schedulerName the workload uses — OpenShift default, Volcano, or KAI later.

Strategic claim

RH AI can adopt Karta with a different scheduler

Karta’s runtime contract is the map CR. Placement stays pluggable. There is no hard dependency on KAI for schema translation or workload submission.
  • Install script never pulls KAI charts or CRDs.
  • Sample PyTorchJob leaves schedulerName empty → default-scheduler.

Takeaways

What to remember

  1. No hard KAI dependency — Karta is schema translation only.
  2. This PoC runs on default-scheduler with Training Operator.
  3. EWI ≠ KAI — consumers of maps are not placement engines.
  4. RH AI can adopt Karta with a different scheduler than Run:ai’s path.

Map the CRD · keep placement pluggable.
