Roadmap question

Can we get away from KAI?

Because of OpenShift / Kubernetes Workload API work, can we bypass the KAI Scheduler by combining Karta, Grove, and the native Workload API?

Yes.

Karta maps schema. Grove shapes cliques. Kueue admits. Workload API + kube-scheduler place. KAI is optional — not required.

Strategic claim

A streamlined AI stack without KAI

Combining Karta, Grove, and OpenShift’s native Workload API creates a streamlined AI stack that eliminates the need to run a secondary scheduler binary like KAI altogether.
  • No hard code dependency on KAI — install script never pulls it.
  • Grove + sample Jobs pin schedulerName: default-scheduler.
  • Gang / all-or-nothing moves to scheduling.k8s.io Workload (+ KEP-6012).

Capability gap

Fractional GPUs without Run:ai

Run:ai’s strength is dynamic fractioning + VRAM swap. On OpenShift, three native-ish paths:

1. Time-slicing

GPU Operator replicas: 4. Pods request nvidia.com/gpu: 1 = one slice. No hard VRAM isolation — noisy neighbor risk.

2. MIG

Hardware partitions on A100/H100. Strict isolation closer to Run:ai memory boundaries; profile resets required.

3. Dynamic slicing

Red Hat Dynamic Accelerator Slicer: on-demand slices via scheduling gates — less idle silicon than static replicas.

  • Docs + samples: fractional-gpus.md · opt-in Helm flags for time-slicing.

Most common path

Time-slicing in practice

ClusterPolicy idea

  • GPU Operator sharing config
  • replicas: 4 → 4 logical GPUs per card
  • Scheduler sees 4 allocatable units

Workload request

  • nvidia.com/gpu: "1" = ~25% time share
  • Ideal for lightweight inference
  • No hard VRAM caps by default

Memory leak in one pod can OOM neighbors on the same physical GPU — unlike Run:ai’s virtual memory spaces.

Takeaways

What to remember

  1. Bypassing KAI is viable — Karta + Grove + Workload API + Kueue cover schema, topology, gang placement, and admission.
  2. No hard KAI dependency — this demo installs none; pods use default-scheduler.
  3. Fractional GPU gap — time-slicing / MIG / Dynamic Accelerator Slicer; not a full Run:ai VRAM↔RAM swap clone.
  4. Keep the translation pattern; align long-term with KEP-6012 + Kueue.
